Expression Tree

What is an Expression Tree?

An expression tree is a tree data structure used to represent an expression, where leaves are operands and internal nodes are operators.

Leaves → Operands
Leaves represent operands such as values or variables (e.g., x, y, 2).
Internal Nodes → Operators
Internal nodes represent operators that act on their child subexpressions (e.g., +, ×, -, ÷).
+ / \ x * / \ y 2

This represents: x + (y × 2)

One Structure, Three Output Forms
Traversal Output Example
Inorder Infix (human-readable) x + (y × 2)
Preorder Prefix + x × y 2
Postorder Postfix (computation-ready) x y 2 × +

Strengths

Why Use Expression Trees? (Advantages)

Four major reasons compilers and database engines rely on trees instead of simple arrays or stacks.

1. No Parentheses Needed
The parent-child tree shape automatically decides operator precedence (like doing multiplication before addition) without needing extra brackets or messy parsing rules.
2. Safe Pre-Calculation
Compilers can safely rewrite messy code, fold constant math like 60 * 60, and remove dead statements before generating final executable code.
Strengths
3. Easy Output Conversion
Walking the tree in different orders produces whatever format you need: In-order gives human-readable code, and Post-order gives assembly/bytecode instructions.
4. Works with Unknown Variables
Unlike stacks that fail when variable values are missing, trees can easily store and optimize expressions containing dynamic variable names like x or y.
Trade-offs

Where Trees Fall Short (Disadvantages)

The extra overhead and performance penalties you pay when using tree data structures.

1. Heavy Memory Consumption
Every single symbol requires its own heap node containing left/right memory pointers, using significantly more memory than a continuous array.
2. Extra Setup Overhead
Before you can use a tree, source code must first be broken into tokens and parsed into nodes—adding build-time delay before work can begin.
Trade-offs
3. Slower CPU Cache Access
Tree nodes are scattered randomly across memory. Jumping around memory pointers is slower for CPU cache than reading linear arrays straight through.
4. Too Complex for Simple Math
If your numbers are already known (e.g. 5 + 3), building a full tree is wasteful overkill compared to using a simple evaluation stack.
Summary

Use a STACK at runtime to calculate concrete numeric values quickly.

Use a TREE at compile-time to inspect, optimize, and transform dynamic program logic.
